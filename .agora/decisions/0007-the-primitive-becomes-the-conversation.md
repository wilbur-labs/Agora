# 0007. 原语从 Run 改成「每个任务一个持续会话」

- **Status**: accepted
- **Date**: 2026-09-07
- **Layer**: task:agora
- **推翻**: `task.yaml` `constraints` 的「原语是 Run（有界调用），不是 Session/对话」（2026-08-27 定，唯一记载处）
- **相关**: [[0001]]（三次身份沿革；其中「议会讨论」被删是**多 agent 自动对话**被否，不是「人与 agent 的对话」被否）

## Context

2026-08-27 的 mockup v2 评审定了四屏界面，用户当时**专门做了 mockup 就是为了不让实现跑偏**。
那次的结论以「UI / 交互决策」一段记进 RESUME，**但没有任何里程碑承接它**——
task.yaml 的 milestones 里 W0/W1/W2/W4/W7/W3/W5/W6 没有一条是「按 mockup 重做界面」。

后果是十一天里每一刀都落在**重定位之前**的那套页面上：导航至今是
`Portfolio / Control Plane / Requirements / Runs / Workflows / Attention / Settings`，
其中 Control Plane / Requirements / Workflows 正是 [[0001]] 判「冻结、UI 不暴露」的
AI-DLC 那一层；mockup 的四屏一个都不存在。W7 甚至把用户六个真实任务塞进了**设置页**的一张卡片里。

2026-09-07 用户指出这件事，并在被问「要 mockup 那个 Run 流 + 消息框（A），还是真正的连续会话（B）」时
**选了 B**。

## Decision

**用户看到的原语是「一个任务 = 一个持续的会话窗口」**：打开任务就是打开对话，输入即继续，
上下文不需要每次重建。

三条边界，缺一条这个决定就会退化成议会时代那套：

1. **底层每一轮仍然是一次可审计的调用。** 会话连续性由**厂商自己的 resume** 提供
   （`codex exec resume <id>` 等），而不是由 Agora 把整段历史重新塞回去。W0(a) 已实测三家 CLI
   都支持按 id 续接，这是这个决定成立的前提。
2. **Run 不消失，降为会话内的工作单元。** 改了哪些文件、门禁结果、复核与重试的嵌套关系——
   这些是 W0(b)~W7 全部诚实性工作的载体，它们继续存在，只是显示在对话流**里面**，
   而不是作为用户要先想清楚才敢点的一次「派活」。
3. **首页仍然不是通用助手入口。** 打开 Agora 落到你的工作上（任务/项目），不是
   「有什么可以帮你的吗」。会话是**任务里的**会话，不是产品的入口形态。

## Consequences

- **三个适配器的会话持久化必须打开。** 现状是被主动关掉的：`codex exec --ephemeral` /
  `claude -p --no-session-persistence` / `kiro-cli chat --no-interactive`，且
  `--no-session-persistence` 与 resume **互斥**（[[0001]] 已记这个前提未解）。这是第一处要改的。
- **session id 成为任务级的持久状态**，要存、要能失效、要能显示「这个会话还在不在」。
  读不到时必须说「不知道」，不能显示成「新对话」——那会悄悄丢掉上下文。
- **与 W3-a 相互作用变强**：远端会话的 id 活在远端，且笔记本合盖后要能续。
  这反而让 W3-a 的「detached + 靠读观察」模型更必要，而不是更不必要。
- **流式输出成为硬需求**：对话窗口里等三分钟没有任何字，等于坏掉。当前是跑完才回。
- 代价诚实记在这里：这比 (A) 大得多。(A) 只是重排现有数据的界面，(B) 要动派发模型。

## Alternatives

1. **(A) 保持 Run 原语，界面做成 Run 流 + 消息框。** mockup 原本的样子，零架构改动，
   一两天能出。**被否（用户当面选 B）**：那仍然是「想清楚一整件事再派一次活」的节奏，
   而用户要的是像本地 gpt/codex 那样边说边改。
2. **每个任务常驻一个活的 CLI 进程（真 REPL）。** 最像「聊天」。**被否**：笔记本合盖即断，
   而 W3-a 的硬验收线正是「合上笔记本 run 不死」；且三家 CLI 的 headless 模式官方支持的是
   resume-by-id，不是长驻交互进程。
3. **会话状态由 Agora 自己持有（存全部历史，每轮重发）。** **被否**：与厂商自己的 session
   重复一份，且 agent 的内部工具状态（读过哪些文件、批准过什么）根本不在文本历史里，
   重发历史拿不回来——那是「看起来连续、实际每轮从零开始」，比不做更糟。
4. **等 W3-a 做完再改原语。** **被否**：W3-a 被公司环境堵着（服务器上一个 agent CLI 都没装，
   装+登录只有用户到公司能做），而这一条今天就能推进，且它决定了 W3-a 要派发的是什么东西。
