## 为什么有 W9

mockup 的第一公民是「**项目**」，实现的第一公民是「**任务**」。三处结构性差异（PROJECT-STATUS §6.8）：
① Today 项目卡三档 ② 工作台左栏 = 项目级导航 ③ 中栏 = 一条 Run 卡片流。

**第一刀选左栏**，判据是 constitution 的 *Reach before polish*：产品唯一真正的差异化（变更 CR / 决策 ADR /
已知缺陷 = 防偏离机制）**现在只能靠手敲 URL 到达**。

顺序：左栏 → 「项目」页（库存视图）→ Today 三档 → 中栏 Run 卡片流（同时结清 W8 验收线 ④）→ 壳/顶栏。

## 已定决策

### D-1 「今天主推」的选择存 Agora 自己的控制平面库

mockup 规定了行为（主推上限 3、「3/3 已满 —— 第 4 个要上来得先放下一个」、紧凑行上有「提升为主推」），
没规定存储。

- 否掉「不存、由 attention 推导」：「提升为主推」是**显式动作**、上限 3 是**人为取舍**，任何信号都推不出
  使用者今天的选择。
- 否掉「写进被读项目的文件（RESUME 之类）」：那需要往别人的 workspace 写文件，撞 `adr/0003`
  （`Environment` 只有 `run`+`probe`，**故意没有写文件能力**）。
- 选控制平面库：这是 **Agora 自己的状态**（使用者的取舍），不是被读项目的事实，与 `adr/0002` 一致。

> ⚠️ 落地前请读 `adr/0002`/`0003` 原文复核（提出该决策时手边没有 ADR 原文）。

### D-2 左栏任务区：只放**当前项目**的工作单元

mockup 左栏没有任务列表 —— 它画的是「一个任务正在进行中」的状态，是**空白不是否决**。但中栏是任务级会话流，
任务必须随时可切，所以左栏要有任务区。**但不是把现有 `TaskRail` 搬过去。**

独立评审的纠正值得记住：**「给已有逻辑找挂载点」不能反过来决定产品 IA**。`lib/rail-group.ts` 的判断规则
可复用，它现有的**展示结构**不是必须保留的资产。

**project-first 的 6 条硬约束**（违反任何一条，就只是把 task-first IA 换了个标题）：

1. 项目名称与项目资源导航**永远居首**
2. 任务**仅限当前项目**
3. 当前任务是项目内上下文，**不是全局对象**
4. **不放项目筛选器**
5. **不展示跨项目 attention**（那属于 Today）
6. 运行**始终嵌套于任务**（承 mockup「按工作单元排，不按进程启动次数排」）

风险判据：任务列表是否又成为页面**最大、最活跃、最具组织权**的元素。

### D-3 W7「其他工作区」面板暂留左栏，但折叠 + 视觉隔离

mockup 左栏没有它，因为 **mockup 画于 2026-08-27，W7 是 09-06/09-07 才完成的** —— 时间顺序，不是否决。
按 *Reach before polish*：它今天够得到，不为对齐一张早于它的设计稿而先让它够不到。

约束：**折叠**、明确标成「其他工作区」、与当前项目导航**视觉隔离**。将来「项目」页可达后**一次原子变更**
迁移，不是先删除后补建。

### D-4 读不到的导航项走统一「能力状态槽」，不做灰色墓碑

mockup 左栏 8 项里 3 项后端无支撑：**已知缺陷**（UI 里完全没有读取）、**技能**
（`backend/agora/skills/` 是空包，v0.4 遗迹，归 W5）、**文件**（无对应读取）。

按 constitution 第二条（「读不到」「不知道」「没有」永不合并），四态：

| 态 | 何时 | 例 |
|---|---|---|
| 数字 | 有可靠读取 | 变更 CR 4 · 决策 ADR 1 |
| **尚未实现** | 功能没建 | 技能（W5） |
| **尚无读取能力** | 东西在但读不到 | 文件 |
| **读取失败** | 运行时读取失败 | 任何一项的 fetch 挂了 |

三者**不能统称「不可用」**。且这些项**仍可点击**，进入说明当前能力边界的页面。

实现约束：`lib/cr-log.ts` 的 `CRLogView`、`lib/portfolio-bucket.ts` 的 `DashboardClaim`、`rail-group.ts`
的 `AttentionReach` 已经是同一类判断。能力状态槽必须**吸收**它们的输出（做映射），**不能另起第四套平行
抽象**。

### D-5 「已知缺陷」的真实读取属于第一刀，但被数据阻塞 → 第一刀拆两步

评审判断：本刀目标不是画出八行导航，而是让 anti-drift 能力真正**可达**；一个打不开真实缺陷信息的
「已知缺陷」入口没有完成该目标 —— 它是这一刀的**最小纵向闭环**，不是 scope creep。范围严格限于：
结构化权威来源 + 列表/计数读取 + 只读页面 + 接通导航。**缺陷编辑 / 生命周期 / 筛选 / 自动发现归后续。**

**但权威来源不在本仓库**：`.agora/development/PROGRESS.md:5688` 自己写着
「Known defects are recorded as **D-1..D-6** in the workspace RESUME」，仓库内其余提及只是零散引用
（`frontend/src/lib/run-column.ts`、两个测试文件），没有结构化记载，也没有 defects 文件。
数字还打架：PROGRESS 说 **D-1..D-6**，mockup（08-27）与 PROJECT-STATUS 都说 **D-1~D-5**。

所以第一刀拆两步：

- **步骤 A（不受阻，进行中）**：左栏改项目级导航 + 能力状态槽 + CR/ADR 接现成端点
  （`/api/projects/{id}/dashboard`、`/api/projects/{id}/decisions`）+ 任务区（D-2 六约束）+ W7 面板折叠
  （D-3）。已知缺陷入口显示「尚无权威来源」（四态之一，可点击进解释页）。
- **步骤 B（等来源）**：结构化缺陷来源（建议 `.agora/defects.yaml`，按 `adr/0004`「CR Log 与 ADR 住在
  项目仓库」推断缺陷也该住仓库 —— **需确认 `adr/0004` 原文**）+ reader + 只读页面。

否掉的第三个选项：从 `PROGRESS.md`（5600+ 行）反向挖出 D-1~D-6 —— 那是**二手推断**，而本项目的规则是
「记录为真」，拿推断当权威来源正是它要防的事。
